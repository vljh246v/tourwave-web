# T-912 인증 모듈 (JWT httpOnly cookie, AuthProvider, useAuth)

## 배경 및 목표

투어웨이브 FE 인증 모듈 구현. httpOnly cookie 전략으로 XSS를 차단하고, React Context + 훅 패턴으로 앱 전역 인증 상태를 관리한다.

## 주요 설계 결정

### 1. httpOnly cookie vs AuthResponse body tokens
서버는 `AuthResponse`에서 body로도 토큰을 반환하지만, T-912 전략은 httpOnly cookie (credentials: 'include').
→ body의 accessToken/refreshToken은 무시하고, 모든 auth fetch에 `credentials: 'include'`를 사용한다.
→ `src/lib/api/client.ts`는 DO-NOT-TOUCH이므로, auth 모듈 전용 fetch를 별도 구성한다.

### 2. user + org 컨텍스트
OpenAPI `MeResponse`는 `{ user: User, memberships: Membership[] }` 구조.
→ `AuthContextType.user`는 `User`, `memberships`는 `Membership[]`, `org`는 첫 번째 ACTIVE membership 편의 파생값.
→ `useAuthGuard(requiredRoles)`: memberships 전체 roles를 평탄화하여 검사.

### 3. 단일 비행 refresh
동시 401 race condition 방지: 모듈 레벨에 `inflightRefresh: Promise | null` 변수로 가드.

### 4. storage.ts 설계
서버가 httpOnly cookie를 소유하므로, FE 측 storage는 토큰을 직접 읽거나 쓰지 않는다.
인터페이스를 thin abstraction으로 유지 (나중에 Bearer 전략 교체 가능하게).
