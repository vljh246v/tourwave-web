# Tourwave UI 설계 스펙

**작성일:** 2026-04-19  
**대상:** tourwave-web 전체 화면 (고객 + 운영자)  
**플랫폼:** Web (반응형) + 모바일 퍼스트

---

## 1. 제품 컨텍스트

Tourwave는 투어·액티비티·레저 스포츠 예약 플랫폼이다.  
**타겟 페르소나:** 20-30대 중후반, 수상·육상·야외 스포츠를 즐기는 활동적 소비자. 어느 정도 지출 여력이 있으며 품질과 경험을 중시한다.

---

## 2. 디자인 시스템

### 2.1 스타일 방향

**Vibrant & Block-based** — 에너지 있고 현대적. 그라디언트는 Hero 영역에만 제한하고, 카드/콘텐츠 영역은 흰 배경 + 사진이 주인공이 되는 구조.

참고 레퍼런스: Klook, GetYourGuide, Airbnb Experiences의 편집적 레이아웃 + 스포츠 브랜드(Nike/Strava)의 타이포그래피 임팩트.

### 2.2 컬러 토큰

| 토큰 | 값 | 용도 |
|------|-----|------|
| `--color-primary` | `#0EA5E9` | 브랜드, 링크, 활성 상태 |
| `--color-primary-dark` | `#0369A1` | 헤더, 강조 텍스트 |
| `--color-secondary` | `#38BDF8` | 보조 강조 |
| `--color-accent` | `#EA580C` | CTA 버튼 (예약, 결제 등 전환 액션) |
| `--color-background` | `#FFFFFF` | 페이지 기본 배경 |
| `--color-surface` | `#F0F9FF` | 카드 배경, 입력 필드 |
| `--color-foreground` | `#0C4A6E` | 본문 텍스트 |
| `--color-muted` | `#64748B` | 부제목, 메타 정보 |
| `--color-border` | `#BAE6FD` | 구분선, 카드 테두리 |
| `--color-destructive` | `#DC2626` | 에러, 삭제 액션 |

### 2.3 타이포그래피

| 역할 | 폰트 | 굵기 | 비고 |
|------|------|------|------|
| 헤딩/브랜드 | Barlow Condensed | 700–800 | 스포티·임팩트, 화면 제목·투어명 |
| 본문/UI | Barlow | 400–600 | 읽기 편안함 |

```css
@import url('https://fonts.googleapis.com/css2?family=Barlow+Condensed:wght@500;600;700;800&family=Barlow:wght@300;400;500;600&display=swap');
```

**타입 스케일:** 10 / 12 / 14 / 16 / 20 / 24 / 32 / 40px  
**본문 최소:** 14px (모바일), 16px (데스크탑)  
**줄간격:** 1.5–1.75 (본문), 1.0–1.2 (헤딩)

### 2.4 간격 시스템

4pt 기반 (4 / 8 / 12 / 16 / 24 / 32 / 48px). Tailwind 기본 스케일 그대로 사용.

### 2.5 컴포넌트 원칙

- 아이콘: **Lucide React** (SVG) — 네비게이션·버튼·기능성 아이콘에 이모지 사용 금지 (역할 선택 카드의 장식적 이모지는 예외)
- 카드 radius: `rounded-xl` (12px)
- 그림자: `shadow-sm` ~ `shadow-md` (과도한 그림자 금지)
- 그라디언트: Hero 배경, 사진 오버레이에만 허용. 카드 배경에 금지.
- 터치 타겟: 최소 44×44px (`min-h-[44px]`)
- CTA 버튼: `bg-[#EA580C]` (오렌지) — 전환 액션 단일 색상 유지
- 비전환 액션: `bg-[#0369A1]` (딥 블루)

### 2.6 반응형 브레이크포인트

| 이름 | 값 | 레이아웃 |
|------|-----|---------|
| mobile | < 768px | 하단 탭바, 1열 |
| tablet | 768–1023px | 상단 네비, 2열 그리드 |
| desktop | ≥ 1024px | 상단 네비, 4열 그리드, 사이드바(운영자) |

## 3. 정보 구조 (IA)

```
공통 진입점
  └─ 로그인 / 회원가입
       └─ 역할 감지
            ├─ 최초 로그인: 역할 선택 화면 (고객 / 운영자)
            └─ 재로그인: 마지막 역할 기준으로 즉시 홈 이동

고객 모드 (하단 4탭)
  ├─ 홈           — 검색바 + 카테고리 칩 + 섹션별 가로스크롤 피드
  ├─ 탐색          — 필터 검색 + 리스트 + 투어 상세 + 예약 흐름
  ├─ 예약 내역     — 탭 (예정 / 완료 / 취소) + QR 티켓
  └─ 마이페이지    — 프로필 + 알림 설정 + 역할 전환 / 로그아웃

운영자 모드 (승인된 계정만)
  ├─ 대시보드      — 오늘 예약 수·매출 요약 + 다가오는 일정
  ├─ 투어 관리     — 투어 목록 + 생성·편집 + Occurrence 캘린더
  ├─ 예약 관리     — 전체 예약 목록 + 상세 + 상태 변경
  └─ 설정          — 프로필·정산 + 고객 모드 전환
```

## 4. 화면별 설계

### 4.1 로그인 / 회원가입

**레이아웃:**  
- 상단 1/3: Ocean Blue 그라디언트 배경 (`#0EA5E9` → `#0369A1`) + TOURWAVE 브랜드
- 하단 2/3: 흰 카드 (border-radius 상단 12px로 겹침)

**입력 요소:**
- 이메일 input (`type="email"`, `autocomplete="email"`)
- 비밀번호 input + show/hide 토글
- 로그인 버튼 (딥 블루)
- 구분선 + Google OAuth 버튼
- 회원가입 링크

**동작:**
- 재로그인 시 역할 선택 화면 생략, 마지막 역할 기준 홈으로 이동
- 첫 로그인 (역할 미설정) → 4.2 역할 선택 화면으로 이동

### 4.2 역할 선택 (최초 1회)

두 개의 선택 카드:
- 🏄 액티비티 즐기기 (고객)
- 🏢 투어 운영하기 (운영자 — 승인된 계정만 노출)

"나중에 언제든 전환 가능" 안내 문구 포함.  
운영자 미승인 계정은 운영자 옵션 비노출 — `useAuth().user.roles` 배열에 `OPERATOR` 포함 여부로 판별.

### 4.3 역할 전환 (헤더 드롭다운)

헤더 우측 아바타 탭 → 드롭다운:
- 현재 모드 표시 (활성 dot)
- 반대 모드로 전환 버튼 (승인된 운영자만 노출)
- 구분선 → 로그아웃

전환 시 URL + 레이아웃 + 탭바 전체 교체.  
고객: `/` 기준, 운영자: `/dashboard` 기준.  
마지막 활성 역할은 서버 세션(httpOnly cookie)에 저장 — 재로그인 시 서버에서 읽어 리다이렉트.

### 4.4 고객 — 홈

**모바일:**
```
[헤더: TOURWAVE 로고 | 아바타]
[검색바: 어떤 액티비티를 찾으세요?]
[카테고리 칩: 전체 / 수상 / 육상 / 투어 / ...]
[섹션: "이번 주 인기" — 가로 스크롤 카드]
[섹션: "서울 근교" — 리스트 카드]
[섹션: "신규 등록" — 가로 스크롤 카드]
[하단 탭바]
```

**데스크탑:**
```
[네비바: 로고 | 홈 탐색 예약내역 | 예약하기(오렌지) | 아바타]
[히어로: 그라디언트 배경 + "지금 바로 떠나는 방법" + 검색바 + 통계]
[섹션별 4열 그리드]
```

**카드 구조:**
- 사진 영역 (상단, gradient overlay로 텍스트 가독성 확보)
- 흰 body: 투어명(Barlow Condensed), 메타(지역·시간), 가격(딥 블루), 별점

### 4.5 고객 — 투어 상세

```
[Hero 사진: 전체폭 + 뒤로/저장 버튼 오버레이]
[투어명: Barlow Condensed 20px+]
[통계: 별점 · 지역 · 소요시간]
[태그 칩: 최대인원 · 장비포함 · 난이도]
[설명 텍스트]
[고정 하단 바: 가격 | "일정 선택 →" 오렌지 CTA]
```

### 4.6 고객 — 예약 흐름 (3단계)

**프로그레스 바** (3단계):  
`날짜 선택` → `인원 선택` → `결제`

- **날짜:** 가로 스크롤 날짜 칩 + 시간 슬롯 (매진 시 취소선 + 비활성)
- **인원:** 카운터 (−/+), 실시간 가격 계산
- **결제:** 주문 요약 + 결제 버튼

각 단계 완료 후 다음 단계 자동 스크롤.

### 4.7 고객 — 예약 내역

탭 3개: `예정` / `완료` / `취소`

예약 카드:
- 상태 배지 (확정: 초록, 대기: 노랑, 취소: 회색)
- 투어명·날짜·인원
- 예정 탭: QR 티켓 버튼 → 인앱 QR 모달

### 4.8 운영자 — 대시보드

**모바일/데스크탑 공통 상단:**
- 오늘 예약 수 / 이번 달 매출 / 다음 일정까지 D-day 요약 카드
- 다가오는 예약 리스트 (투어명·날짜·인원·상태)
- 빠른 액션: "투어 추가", "예약 확인"

**데스크탑:** 좌측 사이드바 네비게이션 (대시보드 / 투어관리 / 예약관리 / 설정)

### 4.9 운영자 — 투어 관리

- 투어 목록 (활성 / 임시저장 탭)
- 투어 생성·편집 폼: 기본정보 · 사진 업로드 · 가격 · 정원
- Occurrence 관리: 캘린더 뷰에서 일정 추가·삭제

### 4.10 운영자 — 예약 관리

- 전체 예약 목록 (날짜·투어·고객·상태·금액)
- 예약 상세: 고객 정보·결제 내역·상태 변경 (확정/취소)

## 6. 핵심 UX 원칙 (ui-ux-pro-max 적용)

1. **터치 타겟 44px 이상** — 모든 버튼·탭·카드 액션
2. **SVG 아이콘** — Lucide React 단일 패밀리, 이모지 금지
3. **Primary Action 하나** — 화면당 오렌지 CTA 1개만
4. **로딩 피드백** — 예약 API 호출 시 버튼 비활성 + 스피너
5. **에러 표시** — 필드 아래에 에러 메시지, aria-live 적용
6. **시간 표시** — 항상 투어 occurrence IANA 타임존 기준
7. **사진 카드** — 사진 없는 투어는 Ocean Blue 플레이스홀더
8. **Skeleton UI** — 데이터 로딩 > 300ms 시 스켈레톤 표시
9. **reduced-motion** — prefers-reduced-motion 존중
